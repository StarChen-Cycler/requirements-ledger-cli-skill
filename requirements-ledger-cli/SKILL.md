# 需求台账 CLI 使用约定

## 查帮助

先用 `reqledger --version` 确认当前入口，再读 `reqledger --help`；按根帮助选择所需命令，逐级查看 `reqledger <子命令路径> --help`。

参数、输入结构、可复制样例、字段限制、状态门禁、返回信息和错误处理均以实际命令帮助为准。本 skill 不维护第二套命令手册。用户指定其他运行入口时使用该入口；命令不可用时说明前提，安装或升级按已有授权处理。

## 理解并使用台账

1. **确定权威文件与本次范围。** 从用户指令和项目约定确认要维护的 MD；当前目录、备份或保留的工作树不自动成为权威来源。只完成本次授权阶段，加载 skill 不意味着要建账或跑完整生命周期。
2. **先整理完整且可读的需求。** 用文字写清行为、可核对的验收条件、包含与排除、边界情况，并关联真实原始来源和适用页面或位置；按帮助表达不适用项，不虚构页面、证据或内容来通过门禁。真正缺失的业务决定由有权决定的人补充。产品功能与项目基础设施需求按项目规则入账，纯属对 Agent 的工作指令不自动转成产品需求。
3. **按事实推进生命周期。** 完整草稿提交复核，按实际审核结果确认后才能形成开发承诺；基线固定精确版本，开发与逐条件验收记录实际进展，发布固定当次交付声明。调整活动承诺时走变更与必要的重新验收；保留旧版本和历史。退役结束后续使用，历史仍保留。
4. **区分各个状态维度。** 内容确认、范围、开发、验收以及发布历史分别核对；新内容修订不能沿用旧版确认来证明已确认。工作提议不等于当前有效基线，开发应采用对应的有效承诺。通过公开查询选择所需视图，通过历史查看当时事实，不把历史修订字段当作当前全部状态。
5. **区分业务迭代与存储维护。** CLI 版本、存储格式、文档修订和对象修订含义不同。存储迁移按当前 `migrate --help` 的兼容范围操作，在授权范围内备份并核对迁移前后的业务内容；文件字节变化不代表需求发生变更，也不必然增加业务修订。

## 写入、核对与恢复

权威 MD 的可读正文和机器记录均由 CLI 维护。Agent 通过 CLI 提交内容，不直接编辑任何一部分；也不把独立 JSON、缓存或数据库作为另一份权威台账。

目标引用从真实响应取得，写入前取需要的最新元信息；已有对象的引用可以按帮助提交，新分配的编号、版本、时间等由 CLI 管理。遇到摘要或修订冲突时重读当前状态，核对意图后重新准备请求。

成功后阅读完整回显，核对实际对象、内容、相关元信息与提交状态；必要时通过公开查询或检查命令复核。退出成功仅说明命令完成，不能替代对结果的核对。

遇到错误时按实际报错及该命令帮助修复。超时或响应丢失导致提交状态不明时，保留原请求与操作标识，先查 `recover --help` 并确认原操作结果再决定重试；不要以新操作盲目重交、覆盖历史或删除锁文件来绕过问题。恢复操作可能取得锁并处理可识别的临时残留，不能当作纯只读查询。

## 责任边界

- **Agent / 调用方负责：** 理解真实需求、核对业务逻辑与来源、提供完整可读的输入、执行或核实真实开发与测试、如实记录证据，并遵守本会话已有授权和项目规则。未完成、未验证或待决定的事项应明确说明。
- **CLI 负责：** 按自身规则验证结构与引用、管理编号版本和历史、维护状态及事务一致性。它不能证明语义正确、来源真实、测试确实执行或产品已部署；字段门禁通过也可能存在业务错误。
- **审核、验收和发布记录是声明。** 操作者标识用于归因，不等于身份认证、真人签字或独立审阅；不得用不同标识伪造独立审核或替实际验证。
- **Skill 只指导台账操作。** 它不自行授权安装、迁移、测试、部署或发布，也不额外要求重复批准已授权工作。其他开发交付工作按其任务约定执行；日常使用 CLI 无需为了加载本 skill 运行开发自测或安装测试工具。
